Client bundle changes (2026-10-03, v2)
======================================

The WinGo client is a minified/hashed webpack bundle, so changes.diff only
covers the PHP engines. These are the exact one-line edits shipped inside the
ZIP (assets/js/), each verified with `node --check`.

1) assets/js/useLottery.hook-_2rEnQ4S.js
   purpose: the running-issue label + countdown used by the bet page

   BEFORE: `B=async(t,a)=>{e.issue=String(BigInt(t.issueNumber)-1n);...}`
   AFTER : `B=async(t,a)=>{e.issue=String(t.issueNumber);...}`

   t is the payload's `current` period (upstream payload already arrives with
   the canonical issue number), so the old -1 made the header show the issue
   of the period that had just ended - the "61 dikha, bet 62 par lagi" bug.
   The served path is `/assets/js/useLottery.hook-_2rEnQ4S.js`
   (index.html -> /assets/js/index-BVjtEoMt.js imports this chunk).

2) assets/js/useWinGo3-5zV6kUzs.js
   purpose: WinGo bet form + GetWinLossResult poll + history list

   a) bet payload
      BEFORE: `...currentIssue=K.value?.current?.issueNumber||B.value;`
      AFTER : `...currentIssue=B.value;`
      B is the live (rollover-advanced) issue; K.value.current is the issue
      captured at the last refresh and can be one period stale.

   b) poll after a successful bet
      BEFORE: `Ie=n=>{u(),m.set(K.value?.current?.issueNumber||B.value,1),`
      AFTER : `Ie=n=>{u(),m.set(B.value,1),`

   c) history list
      BEFORE: `const shiftPublicResults=c=>Array.isArray(c)?c.map((d,i)=>{const n=c[i+1];return n?{...d,number:n.number,color:n.color,premium:n.premium,sum:n.sum}:d}):c;`
      AFTER : `const shiftPublicResults=c=>Array.isArray(c)?c:[];`

      Removed because the server no longer re-labels history rows
      (draw-live-v4/index.php), so re-using the next row's values would pair
      every period with the wrong result.

No other client file was touched. If the site has a service worker or an app
wrapper, clear its cache once after deploying (the file names are hashed but
unchanged, so a plain reload may keep the old chunk in some browsers).
